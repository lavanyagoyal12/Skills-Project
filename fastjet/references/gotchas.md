# Gotchas and sharp edges

Verified against `src/fastjet/*.py`, `src/_ext.cpp`, and the test suite.

## Error catalog

| Exception | When |
|---|---|
| `TypeError` | `data` is not `ak.Array` / list / `dak.Array` / graphed array; `jetdef` is not a `_swig.JetDefinition`; passing an Awkward array to a SWIG-only math helper; graphed input with < 1 list per event; dask method given non-dask data |
| `ValueError` | `exclusive_jets(0, ...)`, `njets <= 0`, `nsub == 0`, `njettiness` with `njets <= 0` or empty, `exclusive_jets` with neither `dcut` nor `n_jets` set (or both), `join` with > 4 args, dask partition incompatibility |
| `RuntimeError` | `exclusive_jets(n_jets > n_particles)` from C++; `get_parents`/`get_child` match failure (`"Jet Not in this ClusterSequence"` — thrown as a raw `const char*`) |
| `AttributeError` | record lacks `px/py/pz/E` and vector behavior was not registered |

## Exclusive jets: the traps

- `exclusive_jets(n_jets=-1, dcut=-1)` — pass **exactly one**; `-1` is the
  "unset" sentinel. Passing both is an error, and `n_jets=0` raises.
- `exclusive_jets(n_jets=4)` on a 3-particle event raises `RuntimeError`; the
  intentional API is `exclusive_jets_up_to(n_jets=4)`, which returns all 3
  constituents (`tests/test_002-exclusive_jets.py::test_exclusive_up_to_multi`).
- `dcut`/exclusive jets for algorithms other than kt, C/A, ee_kt, plugin, or
  genkt with p ≥ 0 get a warning: *"should be interpreted with care"*. The
  C++ warning was patched out (`patch_clustersequence.txt`); Python re-emits it
  and sets `warnings.formatwarning` to FastJet's style.
- `n_exclusive_jets(dcut)` counts jets the exclusive algorithm would produce at
  that dcut — not the number of inclusive jets.

## Parenting queries are by-rapidity matching

`has_parents`, `has_child`, `get_parents`, `get_child` in `_ext.cpp` build
`rap -> index` over the event's inclusive jets and look up the passed jet by
`rap()`. Consequences:

- Only jets generated by this exact `ClusterSequence` can be queried; anything
  else throws.
- Two jets with identical rapidities can be confused (degenerate inputs are
  unsafe for these methods).
- In the multi-event arms the input jet array's first axis must index events.

## Silent dispatch failure

If the `ak.Array` layout matches **no** branch in
`AwkwardClusterSequence.__init__` (e.g. a plain `NumpyArray` without a record),
`_internalrep` is never set and no error is raised at construction time — the
failure surfaces later as `AttributeError: '_internalrep'`. The `raise TypeError`
was commented out (`src/fastjet/_pyjet.py`). Check `cluster._internalrep` first
when a query misbehaves.

## Known bugs / oddities in `_utils.py`

- `sort_indices(indices, values)` recurses into itself for non-Awkward input
  (`return sort_indices(indices, values)`) → `RecursionError`. Use it only via
  its intended SWIG counterpart or sort with awkward (`ak.argsort`).
- `sorted_by_rapidity(data)` calls `_swig.sorted_by_pz` for non-Awkward input
  (copy-paste bug).
- `join` accepts 1–4 arguments; `join(5+ args)` raises `ValueError`.
- `fastjet.__all__ = ("__version__",)` — `from fastjet import *` imports only the
  version (marked TODO in source). Import names explicitly.
- The base `ClusterSequence` docstring names
  `exclusive_jets_constituents_index`, but the real method (all arms) is
  `exclusive_jets_constituent_index`.

## JetDefinition shape shifting

- The public `JetDefinition` re-implements `__init__` to support `R_in=...` as a
  keyword and to add `__getstate__`/`__setstate__` (picklable, needed by Dask and
  graphed). If `R_in` is neither second positional nor keyword, construction
  fails — always pass the radius.
- `R_in` must be real (`int` is coerced to `float`); other types raise
  `TypeError`.
- It subclasses `_swig.JetDefinition`, so `isinstance(jd, fastjet._swig.JetDefinition)`
  is the only type check the dispatcher performs — do not bypass it with
  `JetDefinitionNoCast`.

## Values and types

- The C++ engine reads `starts`/`stops` as **int32** — events beyond ~2³¹
  particles/events overflow; also `_ext.cpp` `output_wrapper` is returned with
  `take_ownership` and keeps every `ClusterSequence` alive until the Python
  wrapper is dropped (memory scales with total events × history).
- Byte order: inputs are normalized with `dtype.newbyteorder("=")`; non-native
  byte order arrays are handled, but conversion happens on the whole arrays.
- `njettiness()` rejects unknown measure/axis strings **silently** (defaults to
  `NormalizedMeasure`/`KT_Axes` in `_ext.cpp`) — pass the exact names listed in
  `api-reference.md`.
- `njettiness` accepts an int or list for `njets`; the default is `[1,2,3,4]`.

## Environment / build

- Requires Python ≥ 3.11; `awkward>=2`, `numpy`, `vector` are hard deps;
  `dask`, `dask-awkward`, `graphed` optional (`[dask]`, `[graphed]`).
- Importing on **Windows** adds `fastjet/bin` to the DLL search path
  (`fastjet/__init__.py`); wheels are repaired with delvewheel.
- Source builds need submodules checked out (`extern/fastjet-core`,
  `extern/fastjet-contrib`) plus `libboost-dev libmpfr-dev libgmp-dev swig
  autoconf libtool` (and CGAL for contrib plugins; pyproject builds it in CI).
  CMake options `SKHEPFJ_USE_INSTALLED_FASTJET[_CONTRIB]` allow linking a system
  FastJet.
- The C++ FastJet banner (version, citation) is printed on `ClusterSequence`
  construction; treat it as normal output and don't treat it as an error.
